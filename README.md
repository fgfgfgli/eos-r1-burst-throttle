# Canon EOS R1 连拍节流研究（burst throttle）

> **一句话**：对 Canon EOS R1（固件 1.3.0）连拍「缓冲写满就停」行为的研究记录——定位判决点、测缓冲水位、试了三轮错误方案，最后用「改写结论」的方式把长时间 busy 变成短停顿。

## 结论

- 连拍的「停」是**前端缓冲写满**造成的（挂起瞬间空位 3/40），不是帧数配额；
- 把「继续拍」（规则 0）改写成「挂起」（规则 1），复用相机自己的挂起路径 ⇒ **非阻塞**的「拍一阵 → 停一下 → 再拍一阵」；
- 早期实测平均约 **15–20 张/秒**，快慢交替；这是当时那组样本的表现，不是固定的降速节奏；
- 自旋方案在「AF-ON 快速切档 + 连拍」下会偶发 Err70，**已放弃**。

### 同一张 2 TB 卡的两次实拍（2026-11-22 / 23）

两次的目标都是 40 张/秒，节流阈值相同，不是固定帧率。22 日通过 USB 加载；拍摄者确认 23 日已对同一张卡执行制卡工具的写入安装。按 CR3 的拍摄时间（分辨率 0.01 秒）计算，每段平均为 `(张数 − 1) / 首末帧时间差`。

| 样本 | 张数 / 时长 | 平均（张/秒） | 按住时的节奏 |
|---|---:|---:|---|
| 22 日，一直按住 | 763 / 41.25 秒 | 18.47 | 起步 4.11 秒约 40 张/秒；全程 762 个帧间隔中，167 个为 140–160 毫秒，最长间隔 420 毫秒 |
| 23 日，第一次按住 | 472 / 25.15 秒 | 18.73 | 起步 5.47 秒约 40 张/秒，随后 19.68 秒平均 12.9 张/秒；最长间隔 90 毫秒 |
| 23 日，松手后再按 | 189 / 7.12 秒 | 26.40 | 开头约 0.58 秒又达到约 40 张/秒，但没有一直维持；最长间隔 90 毫秒 |

23 日两段之间的 **0.66 秒是拍摄者主动松手再按**，不计作相机 busy。只比首次按下后的前 25 秒，22 日拍了 **491 张**，23 日是 **470 张**。因此，23 日按住时出片更均匀，不等于同样时间拍得更多。

回传的两份卡文件分别与工具内置、前一天手工写卡的对应文件哈希一致。能确认的另一处差异是**单张照片的数据量**：22 日约 32–35 MB，23 日约 26.4–28.4 MB。相同帧率下，较小的文件可能让全速维持更久；这不是卡速实测，也不足以解释所有帧间隔。此前两组 USB 测试的重试设定不同，慢段却都出现了约 150 毫秒的间隔。23 日没有拍摄当时的机身状态记录，两天也不是只改变加载方式的对照。**不能单凭 150 毫秒判断补丁开关，也不能断言是 USB 或卡启动造成了差异。**
