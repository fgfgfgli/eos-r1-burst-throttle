# Canon EOS R1 连拍节流研究（burst throttle）

> **一句话**：对 Canon EOS R1（固件 1.3.0）连拍「缓冲写满就停」行为的研究记录——定位判决点、测缓冲水位、试了三轮错误方案，最后用「改写结论」的方式把长时间 busy 变成短停顿。

## 结论

- 连拍的「停」是**前端缓冲写满**造成的（挂起瞬间空位 3/40），不是帧数配额；
- 把「继续拍」（规则 0）改写成「挂起」（规则 1），复用相机自己的挂起路径 ⇒ **非阻塞**的「拍一阵 → 停一下 → 再拍一阵」；
- 早期实测平均约 **15–20 张/秒**，快慢交替；这是当时那组样本的表现，不是固定的降速节奏；
- 自旋方案在「AF-ON 快速切档 + 连拍」下会偶发 Err70，**已放弃**。

### 同一张 2 TB 卡的实测（2026-11-22 / 23 / 27）

三次的目标都是 40 张/秒，节流阈值相同，不是固定帧率。按 CR3 的拍摄时间（分辨率 0.01 秒）计算，每段平均为 `(张数 − 1) / 首末帧时间差`。

| 样本 | 张数 / 时长 | 平均（张/秒） | 按住时的节奏 |
|---|---:|---:|---|
| 22 日，USB 加载 | 763 / 41.25 秒 | 18.47 | 起步 4.11 秒约 40 张/秒；762 个帧间隔中 167 个为 140–160 毫秒；最长 420 毫秒 |
| 23 日，卡启动 | 472 / 25.15 秒 | 18.73 | 起步 5.47 秒约 40 张/秒，随后 19.68 秒平均 12.9 张/秒；最长 90 毫秒 |
| 27 日，卡启动 | 793 / 40.36 秒 | 19.62 | 起步约 5 秒 40 张/秒；无 140–160 毫秒间隔；最长 100 毫秒 |
| 27 日，USB 加载 | 819 / 40.32 秒 | 20.29 | 起步约 5 秒 40 张/秒；无 140–160 毫秒间隔；最长 100 毫秒 |

单张中位：22 日 33.5 MB；23 日 27.2 MB；27 日两次 28.9 / 28.8 MB。

23 日两段之间的 **0.66 秒是拍摄者主动松手再按**，不计作相机 busy。只比首次按下后的前 25 秒：22 日 491 张，23 日 470 张，27 日卡启动 520 张、USB 491 张。

27 日两次是**同场景、同设置、同一张卡**，只换加载方式：先关 BootDisk 重启使卡启动不触发，再经 USB 装载同阈值载荷；拍前均回读确认（桥参数全 0、只剩 USB 页表）。两次结果一致 ⇒ **加载方式不是差异来源**。22 日与 27 日的差别在**单张数据量**（33.5 MB vs 28.8 MB）：大文件时出现 150 毫秒停顿，小文件时没有。这仍是相关性，场景与设置没有逐项对齐。
