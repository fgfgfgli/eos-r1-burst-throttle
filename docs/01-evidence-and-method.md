## 1. 为什么要分级

固件研究里最常见的失败不是"没找到"，而是**把推测当成了事实**，然后在这个假事实上继续搭三层。

这个项目在本轮里就发生过一次：中途认定"副核 `JudgeNext` 算出了非法的传感器模式"，写进了记录，还据此规划了下一步。后来断电重启、在**干净状态**下读同一组字段，发现那些"非法值"是**复位默认值**——推断被撤回（见 [07](07-open-gate-err70.md) §4.3）。

如果当时没有分级，这条错误会一路传下去。

所以本项目强制三档标注：

| 标记 | 含义 | 什么样才算 |
|---|---|---|
| `[V]` | **已验证** | 原始字节可逐字复核，或实机只读回读与预期一致。别人拿着同样的固件/设备能复现 |
| `[I]` | **推断** | 由多条 `[V]` 推出，**必须写明依据**。允许错，但不许含糊 |
| `[?]` | **未知** | 没建立、证据不足、或有互相矛盾的证据。**诚实标注，不算丢人** |

### 使用规则

1. **一条结论只能有一个等级**，取最低的那一环。链上有一环是 `[I]`，整条就是 `[I]`。
2. **`[V]` 必须可复核**：给出虚拟地址、文件偏移或实机读点。给不出 = `[I]`。
3. **`[?]` 不是"待办"**，而是"当前无法判断"。写 `[?]` 时必须写清"缺什么才能判"。
4. **负结论也要标等级，并且必须带边界**。"在这条链的直接调用面里没找到写卡输入"是 `[V]`（有界负证据）；"不存在间接状态输入"是 `[?]`。
5. **外部复核意见不是本项目证据**。引用时写"复核意见认为……"，不升格为 `[V]`。
6. **观测 ≠ 机制。** 在某个配置、某几个窗口里测到的数字，只能写"在该配置下观测到"，不能写成"全模式成立"。
7. **成功一次 ≠ 机制安全。** 一次通过的对照实验只说明"这一次通过"。

> 规则 6 / 7 是本稿在外部复核后**新加**的。原始记录里有多处把有限实验升格成了全称命题，逐条列在 [08](08-review-notes.md) §5.3。

## 2. 地址 ↔ 文件偏移换算

分析对象是固件更新包解出的 `part0_firmware.bin`（R1 1.3.0，114,779,136 B）。它由多个段组成，**每一段有自己的 VA 基址与文件起点**，换算不能混用。

### 2.1 主 AArch64 段

```
VA 范围    0xE0500000 起，长度 43,986,848 B
文件起点   0x000CC7C0
```

```
file_offset = VA − 0xE0500000 + 0x000CC7C0
VA          = file_offset − 0x000CC7C0 + 0xE0500000
```

**这是最常用的一条。** 本文档集里绝大部分地址（`0xE0xxx` / `0xE1xxx` / `0xE2xxx`）都落在这个段里。

### 2.2 数据段 #7

```
VA 基址    0x00004000
文件起点   0x03698768
```

```
file_offset = VA − 0x00004000 + 0x03698768
```

低地址区间（`0x4xxx` 一类小 VA）走这条。

### 2.3 副核（Radon / Xtensa）

副核有自己的**代码镜像**与**数据模块**两段，且**装到 RAM 之后地址会变**：

| 项 | ROM 源（文件内） | 运行期装入点 |
|---|---|---|
| 代码镜像 | `0xE2936688`，长 `0x3EF78`，链接基址 `0xBFF00000` | `0xD4000000` |
| 数据模块 | `0xE2975618`，长 `0x12F88` | `0xD4080000` |

运行期地址 = ROM 源地址 − 该段 ROM 基址 + 装入点基址。

> **勘误（本轮复核发现的算术错误）**：本包上一稿（以及它引用的会话记录早段）曾把数据模块头部两个自指针的重定位量写成 `+0xD000`。
> 正确值是 **`0xDD000`**（`0xBFFDFE4C − 0xBFF02E4C`）。`OG-ERR70-R1.md` §1.4 早已给出正确差值，是发布稿照抄了会话记录里的笔误。
> 这类错误**不会因为源文件这么写就变成对的**——本文档集的做法是重新算一遍。

> ⚠️ 这里有一个**本轮最贵的教训**：数据模块开头两个自指针在装入时被重定位，`+0x08` 起才逐字相同。所以"ROM 里改了就等于运行期改了"是**错的**——运行期有一份独立副本，改 ROM 源不影响它。这个错误让此前所有 6K 实验都跑在"主表与副核表不一致"的状态下（见 [07](07-open-gate-err70.md) §3）。

## 3. 关键地址空间（R1 1.3.0）

**只到"区"这一级**：具体页、页表槽位、副本缓冲与钩子落点不在公开版（见内部记录）。

| 区间 | 用途 | 备注 |
|---|---|---|
| `0xE0500000` | 主镜像 AArch64 **复位入口** | 不是函数：结尾 `bl ...; b .`，**永不返回** |
| `0xE0500000`–`0xE2F00000` | 固件镜像区 | MMU 层 RW（AP=00）；介质只读是 `[I]`（见 [04](04-mmu-and-remap.md) §2） |
| `0xDFFC0000` 起 | 页表 SRAM | 运行期 `TTBR0` / L2 表就在这块；来源是镜像里的一块 blob，启动期整块拷入 |
| `0xD4000000` / `0xD4080000` | Radon 代码 / 数据模块 | Xtensa 副核的运行期装入点 |
| `0x1CC0000` | DAFState（Thumb）镜像 | 连续 AF 的评估代码在子 CPU 侧 |
| `0x44780000` 一带 | FAEXE 程序区（约 1 MB 可执行 RAM） | 回调槽在区内末尾附近；具体偏移不在公开版 |
| `0x09000000` | `AUTOEXEC.bin` 载入点 | 开机后**会被清零** |
| `0x00800000` | `S1_AUTOEXEC.bin` 载入点 | Thumb |
| 页表空洞（地址不在公开版） | 卡启动桥放持久数据的地方 | canary 实测开机后存活；具体页见内部记录 |

**权限结论**：4 GB 空间里绝大部分是恒等映射；EL1 可读写取指，EL0 基本无权限。由页表逐项解码得到 `[V]`，细节见 [04](04-mmu-and-remap.md)。

> 上面这些区间地址**只用于说明结构**。要定位到具体函数/字段，需要自己做地址换算 + 交叉引用扫描——这是刻意保留的门槛。

## 4. 复现的前提

### 4.1 你需要自己准备的

| 项 | 说明 |
|---|---|
| **合法持有的固件** | 从官方更新渠道获取你自己设备的更新包。本项目**不提供**固件、镜像或任何片段 |
| **解密路径** | 本项目**不复述**解密算法、密钥、派生方式与容器细节。你需要自行解决，并自行判断在你所在法域是否可行 |
| **AArch64 反汇编** | 本项目主核分析用 Capstone（BSD-3-Clause） |
| **Xtensa 反汇编** | 副核分析用 **radare2 6.2.6**（`-a xtensa -b 32 -m 0xBFF00000`）+ 自写的指令长度 / `l32r` 字面量 / 字符串 / `call` 目标扫描助手 |
| **地址换算** | 见 §2 的三条公式，二十行代码就能写 |

### 4.2 本项目提供什么

结论、证据等级、机制描述（"改了什么语义"）、失败记录与踩坑（往往比结论更有用）。

### 4.3 本项目**不**提供什么

固件、解密密钥、容器参数、可执行载荷、载荷编解码密钥、补丁指令字、造卡布局与校验偏移、页表槽位与副本地址、跳板/桩布局、写入参数常量、cache/TLB 维护序列、`0x905A` 上传报文格式、一键脚本。

> 这不是遗漏，是**刻意**：公开版是"方法论 + 可讨论的结论"，不是"可照做的流程"。
> 但也要诚实：**保留函数级地址仍然降低了研究门槛**，不能因为"没给机器码"就宣称"这个仓库给不了任何能力"。

## 5. 方法纪律（外部复核意见，`[I]`）

两位外部复核者（`analysis/ROUTE-REVIEW-ASTRA.md`、`analysis/REVIEW-GPT.md`）对本项目的方法提出了几条**直接适用**的批评。这些是复核意见，不是本项目的实测证据，但本项目采纳了它们：

1. **名字必须绑定到真实的引用者与调用边。** "字符串里有个 `BootDisk`"不等于"这条路径会被执行"。PINO、FromUtility、BootDisk 这些名字**不能替代** CPU 身份或可达性判定。
2. **分清数据域。** 机身的 BootDisk 字段、卡上的 `BOOTDISK` 字符串、SCRIPT 标记、工厂字段、S1 模式位——**不能因为名字相近就合并成一个开关**。
3. **零命中只约束"搜索表示法与覆盖范围"。** 扫不到某个模式，只能说明"用这种方法在这个范围里没扫到"。
4. **正例也要限域。** "87 个 wrapper 的完整映射"不等于"全系统模式集合完备"。
5. **更正应按命题与原始证据裁定，不能按文件时间。** 晚出的文档里仍可能残留旧的错误措辞。
6. **反汇编脚本的自动注释不是事实。** 简易寄存器跟踪不处理寄存器改写与调用破坏，跨 `bl` 之后可能保留过时的页基址。结论必须按实际指令逐条追。

## 6. 实验纪律（本项目的血的教训）

| # | 纪律 | 来源 |
|---|---|---|
| 1 | **先跑对照**：任何补丁之前，先跑"只打桩、不改值"的版本。若对照都异常，问题在机制不在值 | 6K：noop 对照通过，才敢说 Err70 来自值改动（但一次通过≠普遍安全） |
| 2 | **"同一载荷结果不一致"先怀疑设备**，不要改代码 | 卡启动：坏卡让整段实验结论作废（见 [02](02-cardboot.md) §5） |
| 3 | **写操作前先确认"这个地址能不能读"** | Peek/Poke 无边界检查 |
| 4 | **故障态里不要再叠加装探针**，先冷启动 | 黑屏状态下装第二个探针 → PTP 任务卡死 |
| 5 | **持久状态与瞬态状态分开记**。RAM-only 的改动断电即恢复；BootDisk 标志、卡上标记与文件是**持久**的 | 见 [02](02-cardboot.md) §6 |
| 6 | **一次只改一个变量**，尤其别同时改表项、谓词与几何 | 6K：三者一起改后"卡得更久"，反而更难归因 |

## 7. 关于"负证据"的写法

本项目有多条负结论，例如"连拍准入链的直接调用面里没有卡/写卡输入"。这类结论必须带**边界**：

> `[V]` 在规则求值函数的 **13 个直接依赖 + 检查函数的 14 个直接被调**范围内，没有一个是 media / CF / SD / 写入队列 API。
> `[?]` **多跳边界没有排除**：job 层完全可能把某个字段写成"卡忙"，再由本链读到。剩余的闸门字段本轮**没有逐个追写者**。

**不能写成**："固件里没有写卡判据。" —— 那是把有界扫描升格成全称命题。
